# Ym1r 小圈子版实施顺序

## 定位

Ym1r 面向本人和少量受邀用户。服务器固定为 `https://example.com/emailbox`，App 登录页不显示或允许修改该地址；每个用户使用独立账号、个人空间、邮箱、笔记与账本。

## 已有能力（直接复用）

- 智能邮件分类、发件人规则和分类筛选。
- 验证码识别、快捷复制与敏感剪贴板处理。
- Android Keystore 加密离线缓存、首屏预加载、离线搜索。
- 邮箱状态桌面组件。
- 指纹/设备密码只解锁本机现有会话，不参与服务器认证。
- 多租户隔离、账号/分组/每日取件配额、管理员后台、设备短码与撤销。

## 阶段 1：访问控制与多人登录

1. 生产设置 `REGISTRATION_MODE=closed`，公开注册接口拒绝请求。
2. App 登录改为用户名 + 密码；服务器地址固定且不显示。
3. 管理后台增加“创建用户”，自动建立个人空间和默认配额。
4. 增加一次性邀请码：管理员生成，受邀者在 App 输入邀请码并设置用户名、密码；邀请码只存哈希、限时、一次使用。
5. 默认用户沿用账号数、分组数、每日取件配额；Ym1r 的租户覆盖值保持 `-1`。

## 阶段 2：笔记替换令牌

1. 新建租户隔离的笔记表与 CRUD API。
2. Android 增加笔记列表、搜索、新建、编辑、置顶和删除。
3. 底部导航把“令牌”替换为“笔记”；令牌维护入口移到“我的/管理工具”，不删除后端刷新能力。
4. 笔记进入本地加密快照，离线只读；联网时写入服务器。

## 阶段 3：同步健康与节点

1. 汇总各邮箱最近同步时间、耗时、错误类型、缓存数量和通知连接状态。
2. 普通用户只看自己的邮箱健康；平台管理员可查看服务器出口节点状态。
3. 节点切换仅允许平台管理员，通过服务端受控接口切换 Mihomo 已存在节点；App 不接触代理订阅、代理密码或 Gmail 凭据。
4. 节点切换审计并提供连通性探测与回退。

## 阶段 4：体验收口

1. 补分类规则管理页及分类/验证码回归用例。
2. 补桌面组件刷新动作和真机重启验收。
3. 更新渠道改为“稳定版 / 测试版”；两者均使用固定 HTTPS 清单并校验 SHA-256，不允许普通用户填写任意地址。
4. 完成账号拖拽排序和设备短码界面。

## 阶段 5：验证与发布

- 每阶段分别跑 Go、Web、Android 测试；后端先部署兼容接口，再发布 App。
- 服务器只组装纯 COPY 镜像，禁止在 1.6G 生产机编译。
- 每次发布前备份 `app.db`、旧镜像和 Compose；App 每次正式发布递增 `versionCode`。
- 稳定版只发布真机验收过的构建；测试版先供 Ym1r 使用。
