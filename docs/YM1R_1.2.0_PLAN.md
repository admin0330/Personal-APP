# Ym1r 1.2.0 规划：邮件智能与个人记账

## 1. 版本目标

- 版本：`1.2.0`，`versionCode = 12`（公网当前正式版为 `1.1.7 (11)`）。
- 正式基线：`https://example.com/emailbox-updates/latest.json` 已于 2026-08-30 实测为 `1.1.7 (11)`。
- 开工前先把本地源码版本声明与公网 1.1.7 对齐；当前工作区 `build.gradle.kts` 仍显示 1.1.0 (4)，不得直接在这个旧版本号上构建或发布。
- 定位：把 Ym1r 从“个人邮箱客户端”升级为“个人邮件与记账中枢”。
- 正式版原则：内部完成自动化测试和真机回归后，直接发布正式版，不复用旧版本号或 APK 文件名。

本版包含六项：验证码识别、智能分类、加密离线缓存、全局搜索、桌面小组件、个人记账。

## 2. 总体数据流

```text
Gmail → 阿里云 Emailbox 拉取 → SSE 通知 App
                              ↓
                     设备端加密邮件缓存
                       ├─ 本地分类
                       ├─ 验证码识别
                       ├─ 全局搜索
                       ├─ 桌面小组件状态
                       └─ 消费邮件 → 待确认账单 → 用户确认 → 服务器记账
```

安全边界保持不变：Gmail 密码、Refresh Token 和 Mihomo 代理只存在阿里云；Android 不直连 Gmail、不内置代理凭据。邮件内容不写服务器新数据库，记账数据通过 HTTPS 同步到现有 Emailbox SQLite，并随服务器数据库备份。

## 3. 页面结构

底部导航调整为：

1. **邮箱**：现有邮箱列表、域名分类和进入邮箱。
2. **记账**：取代原“分组”导航，提供本月概览、快速记一笔、待确认账单、最近记录。
3. **令牌**：仅传统会话模式显示；个人登录密钥模式隐藏。
4. **我的**：固定在末尾，不参与排序。

“邮箱、记账、令牌”均可在设置中调整顺序，修改立即生效；“我的”始终固定在末尾。邮件智能分类作为邮箱列表与离线搜索的筛选维度，不再单独占用底部导航。

全局搜索使用顶栏搜索按钮进入，不额外占用底部导航。

## 4. 功能规格

### 4.1 验证码识别

- 1.2.0 只识别标题、摘要和正文中的**文本验证码**，不做图片 OCR。
- 从邮件标题、摘要以及已打开邮件的正文中识别 4–8 位数字或字母数字验证码。
- 必须同时出现“验证码、verification code、OTP、security code、一次性密码”等上下文，避免把订单号、日期和金额识别成验证码。
- 邮件列表显示“验证码”标签与“一键复制”。复制内容标记为敏感剪贴板，并在 60 秒后尝试清除。
- 验证码默认有效展示 10 分钟；过期后仍可在邮件正文查看，但不再突出显示。
- 锁屏通知和桌面小组件默认不显示验证码正文。

验收：覆盖中英文验证码、无空格验证码、带连字符验证码；订单号、手机号、日期和金额不得误报。

### 4.2 智能分类

固定分类：

- 验证码
- 登录与安全
- 账单与交易
- 购物与物流
- 订阅与 Newsletter
- 其他

规则优先级：用户自定义发件人/域名规则 > 验证码规则 > 安全规则 > 账单规则 > 购物物流规则 > 订阅规则 > 其他。规则全部在设备本地执行，不上传第三方 AI。

“移动到另一分类”只改变 Android 本地标签，不移动 Gmail 邮件、不修改服务器分组。用户调整本地分类时，可选择“以后都这样分类”，生成按租户隔离的发件人或域名规则。规则支持查看和删除；本版不做复杂条件编辑器。

验收：相同输入每次分类一致；自定义规则覆盖内置规则；删除规则后立即恢复内置分类。

### 4.3 加密离线缓存

- 缓存最近 30 天、每个邮箱最多 500 封，同时全局最多 1000 封；设置中可选 7/30/90 天。天数、条数或 200 MB 任一先达到即开始清理。
- 缓存数据库放在 `noBackupFilesDir`，不复用当前明文 `AccountsCache`，不参与系统云备份。
- 标题、发件人、收件人、摘要和已打开正文必须在交给 SQLite 前加密；磁盘、WAL 和临时文件中不得出现这些字段的明文。
- 使用独立 Keystore alias `ym1r_mail_cache_v1`；每条记录使用随机 nonce，并以 `tenant/account/folder/id_mode/message_id` 作为 AES-GCM AAD，防止密文被跨邮件替换。
- 只缓存已打开邮件的正文；不缓存附件，附件仍按需下载。
- 默认磁盘上限 200 MB；超过上限先删除最旧正文，再删除最旧邮件记录。
- 退出登录提供“同时清除本地邮件缓存”，默认勾选；清除时删除主库及 `-wal`/`-shm` 边车文件。Keystore 解密失败时直接丢弃缓存并重新同步，不生成明文降级文件。
- 复用现有首屏预加载，在网络返回后原子更新缓存。

实现选择：使用 Android 原生 SQLite 与 Keystore，不引入同步框架。缓存规模上限约 1000 封，搜索时在内存解密扫描即可；达到数万封后再考虑加密索引。

验收：飞行模式可打开已缓存列表和正文；数据库文件中搜索不到测试邮件明文；升级、重启和进程被杀后缓存仍可读取。

### 4.4 全局搜索

- 搜索范围：全部邮箱的本地加密缓存；页面标题和空状态始终明确写“离线缓存搜索”，不暗示已搜索 Gmail 全部历史。
- 搜索字段：发件人、邮箱地址、主题、摘要和已缓存正文。
- 筛选：邮箱、智能分类、日期范围、未读、含附件。
- 结果明确显示邮箱来源和“离线缓存结果”；未缓存的历史邮件不伪装成已搜索。
- 输入防抖 250 ms，最多显示 100 条；按接收时间倒序。

验收：断网仍可搜索；中文、英文和邮箱地址可命中；清除缓存后结果同步清空；搜索过程中不记录查询词或邮件正文到日志。

### 4.5 桌面小组件

1.2.0 只提供一个简洁组件，所有数字来自设备本地缓存，不新增不准确的“服务端全局未读”协议：

- 展示“缓存未读”总数、已缓存邮箱数量、最后同步时间和当前拉取状态；不把邮箱数量硬编码为两个。
- 点击组件打开邮箱主页；点击刷新进入 App 并触发一次同步。组件本身不在后台直接联网。
- SSE 收到新邮件或 App 完成拉取后刷新组件。
- 默认不显示主题、发件人、验证码或记账金额，避免锁屏和桌面泄露。
- 设备重启后从持久化聚合快照恢复；超过缓存有效期显示“待同步”，不能继续展示成实时数据。

实现选择：使用原生 `AppWidgetProvider + RemoteViews`，不为一个静态组件增加 Glance/WorkManager 依赖。

验收：添加、调整尺寸、设备重启、App 锁定、离线和新邮件到达场景均能保持正确状态。

### 4.6 个人记账

#### 4.6.1 首版范围

- 快速记账：支出、收入；金额、分类、时间、商户/来源、备注。
- 默认分类：餐饮、交通、购物、订阅、住房、医疗、数码服务、工资、其他。
- 本月概览：收入、支出、结余，按分类显示金额与占比。
- 最近记录：查看、编辑、删除。
- 支持 CNY、USD、HKD；不同币种分别统计，不自动换汇。
- “账单与交易”邮件可以提取金额、币种、商户和时间，生成**待确认账单**。用户确认或修改后才入账，绝不自动记账。
- 同一封邮件只能生成一条待确认记录，通过 `tenant + account + folder + id_mode + message_id` 去重。
- 账本按 `tenant_id` 隔离，不按设备隔离；同一租户后续可在其他设备读取同一账本。

#### 4.6.2 数据与同步

记账以服务器为主数据源，Android 保存本地加密快照用于秒开和离线浏览。离线新增记录保存到本地待同步队列，恢复网络后按客户端生成的 UUID 幂等提交。

服务器最小数据表：

```text
ledger_transactions
- id (UUID, primary key)
- tenant_id
- type (expense/income)
- amount_minor (integer，禁止浮点金额)
- currency (CNY/USD/HKD)
- category
- merchant
- note
- occurred_at
- source (manual/email)
- source_message_key (nullable, unique per tenant)
- created_at / updated_at / deleted_at
- client_id (客户端 UUID，用于离线新增幂等)
```

约束：`amount_minor` 必须是正整数，由 `type` 表示收入或支出；`occurred_at` 使用带时区 RFC3339，服务器统一存 UTC，月度汇总固定按 `Asia/Hong_Kong` 切月；邮件来源记录必须有 `source_message_key`，并建立租户级条件唯一索引；`(tenant_id, client_id)` 必须唯一。

最小 API：

```text
GET    /api/v1/tenants/:tenantID/ledger/transactions
POST   /api/v1/tenants/:tenantID/ledger/transactions
PATCH  /api/v1/tenants/:tenantID/ledger/transactions/:id
DELETE /api/v1/tenants/:tenantID/ledger/transactions/:id
GET    /api/v1/tenants/:tenantID/ledger/summary?month=YYYY-MM
```

服务器为 API Key 增加显式 scope。既有 Key 保留原权限，不做隐式升级；新生成的个人登录密钥默认拥有 `mail:read + ledger:read + ledger:write`，以保证单密钥登录后的邮件与记账功能同时可用。2026-08-30 已对实际供 Ym1r App 使用的既有 `admin` 工作空间 Key 做一次明确授权，未开放任何邮件写权限。Android 出网闸门只精确放行上述 `/ledger/transactions` 的 POST/PATCH/DELETE，不能借此写邮箱、账号或令牌接口。

离线队列首版只支持“新增记录”：POST 必须携带 `client_id`，超时重试返回同一记录。401/403 立即停止队列并要求重新授权；404 标记永久失败；409 拉取同一 `client_id` 的服务器记录后完成对账；429、502 与网络错误按 5/30/120/600 秒有限退避，最多 5 次后等待用户手动重试。离线编辑与删除在 1.2.0 明确禁用，联网后才能执行，避免引入冲突合并系统。

验收：金额全部按最小货币单位整数存储；重复提交不重复记账；离线新增恢复联网后只同步一次；越权租户访问返回 403/404；服务端备份恢复后账目完整。

## 5. 实施顺序

### 阶段 A：数据基础

- 核对并固化公网 1.1.7 正式基线，解决本地版本声明落后问题。
- 新增加密邮件缓存、缓存迁移/清理和测试。
- 新增服务器记账迁移、权限和 CRUD API。

### 阶段 B：邮件智能

- 验证码解析器及误报测试。
- 分类规则引擎及自定义覆盖规则。
- 全局搜索和筛选。

### 阶段 C：记账

- 记账主页、快速新增、编辑删除和月度概览。
- 邮件账单提取与待确认流程。
- 离线队列和服务器幂等同步。

### 阶段 D：桌面组件与整体验收

- 原生桌面组件。
- 真机验证弱网、离线、重启、指纹锁、SSE、新邮件、搜索和记账同步。
- 构建签名 Release，递增到 `versionCode 12`，更新清单后正式发布。

## 6. 必须保留的安全限制

- 不把 Gmail 凭据、登录密钥、邮件正文、验证码或记账备注写入日志。
- 不在桌面组件和锁屏通知默认显示敏感正文。
- 邮件账单只能建议，不能自动入账。
- 不使用浮点数保存金额。
- 不让个人登录密钥获得邮箱写权限。
- 服务器迁移前备份 `/opt/emailbox/data` 和旧镜像；Android 数据迁移失败时保留服务器主数据并允许重新同步。

## 7. 本版明确不做

- 银行卡/支付宝/微信自动接入。
- 发票 OCR、AI 邮件总结或第三方云端分类。
- 自动汇率与投资资产管理。
- 附件离线缓存。
- 完整历史 Gmail 服务端索引。
- 多人共享账本和复杂预算系统。

这些功能等实际使用中出现明确需求后再增加，避免 1.2.0 变成不可验收的大杂烩。
